# ALPHA Hybrid AI Fleet — controlled staging protocol

**Phase:** HYB-002 / 2026-10-24. **STATUS: OFFLINE-ONLY implementation; live ChatGPT-to-ChatGPT orchestration NOT active.** No cloud deployments, external provider calls, model/API billing, production operations, messages to creators, or auto-triggers are performed by this module.

## Architecture and bounded roles

1. **ChatGPT Account 1 (Executive):** prepares a TASK intent. A separately controlled Captain-approved signing process signs it; the account cannot know or export the Captain private signing key.
2. **Signed bridge (future, not installed):** carries exact signed JSON, with authenticated provider metadata preserved. The pure `parseExecutiveComment` helper accepts provider-verified `repository`, `issue`, `actor` context, and rejects other sources. **Existing private GitHub Issue #3 expressly forbids autonomous polling and retries. Do not connect it to an automated transport without separate Captain authorization.**
3. **Engineering / Account 2:** independently retrieves and inspects an authorized TASK. The Engineering worker may sign an ACK and one allowlisted result; AI Account 2 is not silently given broad repository privileges.
4. **Autopilot:** `pilot.mjs process-file` is a one-task, one-shot runtime **disabled by default**. It requires owner-approved public-key pin and explicit enable flag. Only `SHA256_EVIDENCE` with <=500 UTF-8 bytes in staging scope is accepted.
5. **Executive verification:** independently checks worker result, then signs a `VERIFIED_STAGING_ONLY` receipt. Cryptographic validation is not by itself proof of authorized human approvals.

## Verify without credentials or API access

Prerequisite Node.js 20+; zero npm dependencies. From repository root:

```sh
node --test tools/alpha-hybrid-pilot/*.test.mjs
node tools/alpha-hybrid-pilot/pilot.mjs demo
```

All test identities are throwaway Ed25519 keypairs generated by the local test runner, **not** actual ChatGPT Account 1, Account 2, or Captain keys. Tests prove code behavior only. The repository contains no secrets. A read-only GitHub Actions workflow uses `contents: read`, no environment secrets, no checkout of private accounts, no API access, and no deploy step.

## One-shot CLI after authorization (NOT activated)

A Captain/operator must independently pin the SHA-256 fingerprint of Executive **SPKI DER** public verification key through an out-of-band trust decision, and separately secure the Engineering worker's signing private key. *Do not generate, ask for, store, or publish the Captain private key.* Do not copy self-asserted key fingerprints from AI-generated comments into the trusted pin.

Supply environment variables from an approved secret store:

| Variable | Requirement |
|---|---|
| `ALPHA_PILOT_ENABLED` | Must be explicitly `YES`; unset/`NO` is STOP |
| `ALPHA_EXEC_PUBLIC_KEY_FILE` | independently approved PEM public key, local file |
| `ALPHA_EXEC_PIN_SHA256` | independently approved lowercase 64-character SPKI SHA-256 pin |
| `ALPHA_WORKER_PRIVATE_KEY_FILE` | protected local **Engineering worker** Ed25519 private key, not Captain key |
| `ALPHA_PILOT_JOURNAL` | private durable replay-claim directory |

Only after explicitly authorizing pilot activation:

```sh
node tools/alpha-hybrid-pilot/pilot.mjs process-file /secure/signed-task.json
```

The CLI has **zero network API calls**; it consumes a locally provided envelope, verifies authorization, claims the task once, and prints a signed receipt. It does not send a GitHub ACK/RESULT, invoke LLMs or schedule jobs. Atomic journal claims prevent normal replay; **the operator must provide a persistent, access-controlled directory and retain it across restarts**, since deleting it would defeat replay history. `ALPHA_PILOT_ENABLED=NO` stops **future** task starts, not work already in progress.

## Failed, canceled and processing events

`POST /api/financials/mock-status-webhooks` accepts the existing operationId/rawJson/signature DTO. It resolves frozen bound/recovered identity and server profile and verifies raw-body HMAC, timestamp, test mode, event/status pair, zero amount_received, frozen amount/USD and merchant/module/campaign/source/profile attribution. Supported pairs are payment_failed/requires_payment_method, canceled/canceled and processing/processing. Connect and ordinary provider IDs are refused. Non-cash evidence can be recorded after source revocation; cash capture still requires current source approval.

Status evidence is append-only and globally conflicts with capture/receipt event IDs. Same-content replay is idempotent; changed body or attribution under the original ID conflicts. Profile cannot be rebound after a status observation. Failed and processing observations write no cash and can precede later simulated success. Cancellation before capture prevents automatic capture until a separately reviewed resolution is implemented. Late cancellation after capture preserves the journal and marks review required. No event silently reverses cash or releases funds.

Advertiser-owned module readings now include mock reconciliation state. CAPTURED_TEST_ONLY takes precedence over late non-cash observations; CANCELED_REVIEW_REQUIRED or MANUAL_REVIEW_TEST_ONLY explicitly signals review. RECOVERED_PENDING_CALLBACK is not paid.

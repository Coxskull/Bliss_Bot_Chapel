## Explicit scope and bounded queue

New mock review routes require authenticated operator/admin role plus a server-configured `MockReviewerScope` matching the stable subject and financial merchant/module/campaign. Empty grants deny access; admin role does not bypass scope registration. Grants map only to registered funding bindings with exact quote version, merchant/module/campaign, recipient and advertiser subject. No actor, scope, amount or payee can be granted through review request bodies. Disabled, Sandbox/Live and non-loopback configurations remain refused.

`GET /api/financials/mock-review/queue` lists cancellation exceptions and aged unresolved operations using full scoped SQL predicates. Optional module filter is validated. Limit is1–100; Guid keyset pagination uses after/nextAfter and deterministic operation-ID order. Registered authorities are capped at128. New cases can appear before a cursor; refresh the first page to see changing queue membership. Current exception flags are computed from financial facts, not note counts or implied reviewer approval.

## Versioned evidence and history

`GET /api/financials/mock-review/cases/{operationId}` returns a repeatable-read snapshot, review reason/flag, SHA-256 fingerprint of PostgreSQL's canonical JSON text and up to200 immutable annotations with an explicit notesTruncated flag. The snapshot includes frozen operation/quote, retry aliases, attempts/results, recoveries, status events, provider binding/callback evidence, captures, linked original/refund journals and lines, receipts, refund requests/results and provider refund IDs. Monetary minor-unit values are exact integer strings. This snapshot excludes notes themselves so independent annotations do not invalidate one another.

The evidence version covers private persisted financial facts and the computed review flag. It does not snapshot current public Economics approval state or external provider/account records. Frozen quote authority is shown; existing preparation/capture adapters still enforce current source approval separately. An annotation never becomes payment authority.

`POST /api/financials/mock-review/notes` takes operationId, evidenceFingerprint, note and idempotencyKey only. Authenticated actor identity comes from the server. CSRF and write-rate controls apply. Text is bounded to2000 characters and stored as plain data; retry key is bounded to120. The actor/key is globally bound to one immutable annotation. Same-content retries return its ID, even after later evidence changes; changed case/version/text under the key conflict. The response explicitly says approvalGranted=false, holdReleased=false and paymentCompleted=false.

Before a new note commits, the mock store takes a conservative short SHARE/NOWAIT freeze on the financial evidence tables, reloads current evidence and compares the expected version and current review flag. Active writers return a safe conflict; stale evidence requires refresh. No network/provider I/O occurs while locks are held. This mock-only coarse freeze prevents concurrent financial commits from making the new annotation target silently stale; a hosted design needs reviewed finer-grained locking and performance acceptance before activation. Notes never update financial tables, clear an exception, release cancellation, approve funds or grant review authority.

`GET /api/financials/mock-review/notes/{noteId}` returns the immutable annotation and its stored historical evidence, under the same current scope checks. Fingerprints can be verified against that exact JSON text after the live case changes. Case note lists explicitly indicate truncation; individual historical snapshots remain retrievable by authorized note ID. Complete note-list pagination is future UI/API work.

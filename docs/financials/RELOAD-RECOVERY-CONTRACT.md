# AGM-LAUNCH-010 R13 — tab-scoped uncertain annotation recovery

Extends existing read-only exact actor/key retry lookup and authenticated Bliss mock review UI. Before an annotation POST, same-origin sessionStorage records a bounded versioned tuple: server-derived actor pseudonym, operation ID, evidence fingerprint, retry UUID and SHA256 note digest. No note text, CSRF/session token, amount, recipient or financial authority is persisted. Mandatory storage write/readback failure prevents POST. Browser tab closure/storage deletion can lose the locator; this is not a durable server approval queue.

Authenticated recovery-context uses existing staff/scope/Mock-only/loopback guards and returns a purpose-separated hash of server subject. It is a correlation pseudonym, not authentication or permission. Every actual retry/history call still derives actor and scopes server-side. Another reviewer cannot recover the original tuple through this UI; malformed storage fails closed. XSS/browser access can read/modify client storage, so it is never financial authority. Digests are not encryption and low-entropy note content may be guessed.

Startup restores an unresolved tuple after session/context verification, blocks new writes/filters/case switching and offers an explicit read-only history check. Never automatically retries POST. Explicit absent retry remains unknown; only matched actor/operation/fingerprint/note digest plus scoped historical reads clear the tuple. Current server scopes can revoke recovery access. No approval/quorum/hold release/cancellation policy acceptance is introduced.

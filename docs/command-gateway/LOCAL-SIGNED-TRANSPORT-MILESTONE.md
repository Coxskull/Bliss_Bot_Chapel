# AGM-LAUNCH-011 local signed transport boundary

Built from externally merged PR179. No existing production authentication changes.

Pinned server-owned registry maps bounded key IDs to public RSA keys and current envelope policy. Request validation derives identity from that registration; submitted sender/tenant/payload never grant permissions. Canonical envelope SHA256, key ID, audience, fixed POST/local inbox route, protocol/kind/RS256 and UTC issue/expiry fields form the signed transcript. RSA2048–4096 PKCS1/SHA256 only, no selectable algorithm or network key discovery. Signature lifetime at most2 minutes,5-second future skew, expiry no later than envelope expiry; key disable/removal checked per admission. Envelope validation and durable retry/causation/audit logic reused.

Gateway signs acceptance only after inbox commit. Receipt binds exact message/hash, tenant/sender/recipient, configured gateway identity, accepted time, replay status, key ID, audience and bounded validity. Client must verify pinned gateway trust and its own expected canonical submission. A signed acceptance is not delivery, execution, independent QA or owner acceptance. Signed retries remain at-least-once and can return original accepted time. Response/signing failure after commit can leave accepted work; exact authenticated retry recovers it without duplicate inbox/audit/intent. A lost response is not proof of failed acceptance.

Keys are ephemeral in-memory RSA test fixtures, never real credentials. Adapter is unregistered and in-process only. This demonstrates cryptographic contract plus durable acceptance, not an HTTP/TLS service, OAuth/OIDC onboarding, genuine autonomous AI exchange or Codex execution. No provider/model calls, paid activation, hosted schema, new resources, credentials changed, merge/deploy. Request authentication is evaluated at admission; no continuous revocation or external cancellation claim. Envelope expiry remains rechecked by inbox after DB lock. Signature bytes/base64 parser and JSON boundary hosting limits must be enforced by a future HTTP adapter; no anonymous existing API endpoints are added.

Tests: canonical equivalence; altered body/message/retry key/signature/timestamps; wrong/unknown keys and audience; expired/future/overlong windows; signature outliving envelope; sender spoof; registry disable/removal/mismatch; malformed/weak keys; receipt field tampering, wrong trust/audience/expected submission, expiry and request/receipt domain separation;12 concurrent authenticated exact retries; response-signing failure after commit and adapter reconnect; unauthenticated request leaves no accepted message. Existing quota/stop and inbox tests retained.

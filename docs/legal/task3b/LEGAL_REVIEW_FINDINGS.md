3. Update UI, JS, server version constants, receipt schema expectations and exact-version source tests **in one reviewed change**; test checkbox independence and false marketing default.
4. Fail closed if the approved legal/version/release configuration is missing; verify actual staged deployment gate, not just visible text.
5. In approved isolated host: test verified email/OIDC, unauthorized user denial, duplicate/idempotent submission, receipt versions and timestamp/identity linkage, pending-review access denial, and negative tenant access.
6. Verify real account-rights intake and lawful retention/deletion/withdrawal route, plus recipient/transfer accuracy.
7. Obtain independent counsel and owner approval; no merge or live registration solely on source CI.

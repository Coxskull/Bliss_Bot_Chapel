# Harborlight acceptance phases

**Date:** 2026-10-07  
**Status:** HV-0 is the decision in this document. HV-1 through HV-5 do not start until the owner approves the provider and the cost ceiling.  
**Parent amendments:** Creative Academy and Advertising Real Estate both stay OPEN.

These phases continue from the implementation that is already built. They do not rebuild registration, LEARN and DO NOT COPY notes, provenance, selective retrieval, geometry, recomposition, the REGENERATE check, the seven Ask Alpha scenarios, or the conversation ledger. Missing prices, delivery, quality grades, and production evidence stay missing until a real source exists.

Infrastructure readiness is not production acceptance. One controlled Harborlight voyage is the next production milestone.

## Provider decision — answer before any spend

No purchase is made by this document. No new subscription is requested.

`gpt-image-1` is scheduled for deprecation on 2026-10-23. If approval comes after that date, HV-1 uses the successor model on the same OpenAI API account. That change is a model setting, not a new subscription.

The proposed ceiling for this voyage is **$2.00**. The run stops and asks before a third paid generation. The provider invoice is the cost of record. This estimate is not a recorded cost.

## Standing rules

- Do not mark either parent amendment complete.
- Do not invent an Economics price, a duration price, a discount, a quality grade, a regression pass, a delivery count, or a hosted acceptance.
- Do not send Academy reference image files to the provider.
- Do not manually pick references to force a success, and do not coach the image into a prototype's identity, person, product, wording, background, or composition.
- Do not put credentials in source control, reports, or screenshots.
- A failed generation is kept. One controlled retry is allowed inside the cost ceiling.
- Delivery remains `NOT_SENT`. A later simulated delivery, if separately authorized, must be labeled `TEST/SIMULATED` and must not be described as a real campaign.
- Economics remains `NO_AUTHORIZED_PRICE` until authorized commercial values are supplied on a separate track.

## HV-1 — Configure the existing adapter

**Purpose.** Point the installed generator at the approved account after HV-0 approval.

**Reuse.** `Runtime:CreativeGeneration:Provider=OpenAI`, `Model`, and `ApiToken` or `ApiToken_FILE` from the platform secret store. Rotate the temporary key that was pasted in chat. The new key is not written into git, reports, or screenshots.

**Change allowed.** Set quality `high` on the existing OpenAI request body, and record provider, model, job identifier, attempt count, and the invoice amount the provider returns. Do not add a second generator.

**Done when.** Configuration is present only in the secret store, a redacted reading says the provider is configured, and no live Harborlight image has been requested yet.

## HV-2 — One Harborlight voyage

**Purpose.** Let the existing voyage produce one new Harborlight Pharmacy advertisement for Panama City.

**Flow.** Brief, automatic Academy retrieval, retrieval reasons, LEARN and DO NOT COPY notes, GQD-1, new creative DNA, art direction, original generation, inventory recomposition, originality check. Visual QA and human review are HV-4. They are not invented during generation.

**Reuse.** The acceptance-voyage orchestrator, selective retrieval, stored geometry, and recomposition. The creative is recomposed into the stored ARE-P01 slots. It is not a scaled prototype.

**Done when.** One voyage record contains the finished image or a recorded provider failure, the job identifier, the attempt count, and the actual cost. Campaign ready stays false. Delivery stays `NOT_SENT`. Model calls are the real calls, not a guessed count.

## HV-3 — Evidence package

**Purpose.** Publish the voyage without hiding a failed attempt.

The package contains the Harborlight brief, automatically retrieved references, retrieval reasons, LEARN and DO NOT COPY notes, the Quality DNA version used, the new creative DNA, provider, model, job identifier, generation attempts, the finished original, the inventory-adapted creative, the originality result, visual QA, deterministic QA where it applies, failures and retries, the human-review result, actual usage, actual cost, and the workflow trace.

**Done when.** Every item above is either stored evidence or an explicit `NOT_RUN` / `UNRECORDED` fact. No item is filled with a placeholder image or an invented number.

**Progress.** HV-001 now stores a thirteen-step workflow trace. Visual QA is `NOT_RUN`, human review is `NOT_REQUESTED`, delivery is `NOT_SENT`, and regression is `BASELINE_NOT_RECORDED`. Changing the human-review step to an acceptance is refused.

## HV-4 — Human visual review and Quality DNA

**Purpose.** A person judges whether the finished creative reaches the Academy visual class: commercial color, saturation, contrast, highlights, shadows, lighting, materials, people when applicable, depth, separation, typography, hierarchy, polish, screen impact, and Premium Dominant Presence. The same review checks that the creative did not copy a prototype's company, identity, person, product, photograph, wording, background, composition, or distinctive identity.

**Quality DNA.** GQD-1 stays the attribute list. Grades stay `UNCLASSIFIED` until a human classifies a specific attribute from evidence. The phase prepares the attribute list for that review. It does not write scores to complete the field.

**Progress.** The HV-001 review sheet is prepared. All sixteen GQD-1 grades are `UNCLASSIFIED`. Copy checks are `NOT_REVIEWED`. Panama-market authenticity and the adapted layout are `UNRECORDED`. Human review remains `NOT_REQUESTED`. Pixel distances to the four retrieved references are `MEASURED` and `NOT_JUDGED`. They are not grades.

**Done when.** The human review result is recorded by the owner. Unreviewed attributes remain `UNCLASSIFIED`.

## HV-5 — Regression baseline

**Purpose.** After, and only after, the owner accepts the finished creative, store that accepted image as the Creative Quality Regression baseline.

**Done when.** The suite can name the accepted baseline asset. It is not marked passed merely because an API returned HTTP 200. Until an accepted creative exists, the suite stays `BASELINE_NOT_RECORDED`.

# Alpha long-term architecture

**Status:** architectural reference only. Not an Engineering Contract.
Not authorization to build the systems named here.

This folder records the updated cost-engineered Alpha architecture for
Wedding Planner, Fishing Fleet, and the Autonomous Demo Factory. It
supersedes earlier combined acquisition blueprints for **future**
contracts.

## What this folder does not do

- It does not open, pause, or redesign current Bliss Chapel work.
- It does not change Wedding Planner Phase 1, Economics Phases 1–9, or
  Bliss Phases 1–20.
- It does not add a provider, subscription, schema, API, or workflow.
- It does not authorize the future contracts listed in
  `FUTURE-CONTRACTS.md`.

The existing Bliss package must reach its required acceptance point
before this future infrastructure is developed. Each later piece starts
only through its own Engineering Contract
(`ENGINEERING-CONTRACT-RULE.md`).

accepted contract governs the code that contract authorized. If it
conflicts with Wedding Planner blueprint v1.1 on long-term acquisition,
source media, decision-makers, cost, or factory behavior, this folder
governs the next contracts. v1.1 remains the product note for the
Wedding Planner module already started.

## Governing economic rule

1. Reuse before generate.
2. Software before AI.
3. A cheap suitable model before an expensive model.
4. Spend more only after engagement.
5. Never pay AI twice to rediscover information Alpha already knows.
6. No new subscription without a capability-gap review.
